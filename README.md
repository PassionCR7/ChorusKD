# ChorusKD

**黑盒知识蒸馏的最优形态：多样采样 + 一致性筛选 + 能力匹配调度 + 在线策略**

[![Python](https://img.shields.io/badge/python-3.10%2B-blue)](https://www.python.org/)
[![PyTorch](https://img.shields.io/badge/pytorch-2.1%2B-ee4c2c)](https://pytorch.org/)
[![License](https://img.shields.io/badge/license-MIT-green)](LICENSE)

针对只能拿到文本输出的闭源 API 教师在做的蒸馏。与白盒蒸馏
（[LensKD](https://github.com/PassionCR7/LensKD)）互补，解决的是完全不同的问题。

> **[LensKD](https://github.com/PassionCR7/LensKD)** — 白盒蒸馏：双投影器跨词表对齐 + 熵门控 + 在线策略
> **ChorusKD**（本仓库）— 黑盒蒸馏：多样采样 + 一致性投票 + 能力调度 + 排序 DPO

---

## 黑盒蒸馏的信息上限

白盒能拿到教师的 `hidden`、`logits`、每层激活。黑盒只有一条通道：发 prompt，收字符串。

这意味着**所有"从分布里榨信息"的手段全部失效**：

| 白盒能做 | 黑盒替代方案 | 信息损失 |
|---|---|---|
| 软标签 KL（完整 151936 维分布） | n 次采样的经验频率 | 严重：n 通常只有 3~8 |
| 表征对齐（逐层 hidden） | 无 | 完全不可用 |
| 温度缩放读分布形状 | 温度铺开采样，观察答案分裂 | 只能估粗粒度多峰性 |
| 教师置信度（分布熵） | 自一致性投票 | 间接、有噪声 |
| 在线策略（教师给学生 prefix 打分） | 教师**排序**学生候选 | 只剩相对偏好 |

**认清这一点是设计的前提。** 黑盒蒸馏的工程重点不是"复现白盒算法"，
而是：
1. 有限预算内怎么问到信息量最大的问题
2. 怎么把幻觉率压到最低
3. 怎么处理教师答不好的样本（黑盒无法区分"不会"和"不想"）

## 七个阶段

```
┌────────────────────────────────────────────────────────────┐
│ Round r                                                    │
│                                                            │
│  P 策展    种子池 → 学生打分 → 按难度档位选题                │
│     ↓                                                      │
│  Q 采样    每题 n 次，温度从 0.3 铺到 1.3                    │
│     ↓                                                      │
│  R 筛选    一致性投票 → 剔幻觉/退化/太易太难                 │
│     ↓                                                      │
│  T 组装    多正例 + 一致性加权                              │
│     ↓                                                      │
│  U 在线    学生自采样 → 教师 listwise 排序 → DPO 偏好对      │
│     ↓                                                      │
│  W 训练    CE(+多正例) + DPO                                │
│     ↓                                                      │
│  S 调度    看本轮 loss → 调整下一轮难度档位                  │
└────────────────────────────────────────────────────────────┘
```

多轮闭环是本仓库与"一次性造数据再 SFT"的本质区别：后者是静态数据集，
前者是**闭环控制器**。学生能力在变，问题难度必须跟着变。

## 各阶段的核心决策

### P · 为什么题目选择比采样次数重要

黑盒按量计费。随机抽问题会把预算浪费在学生已经会了的内容上。

用**学生在该问题上的 loss** 做难度代理（不是教师的 loss——要教的是
"学生跳一跳够得着"的内容，不是"教师觉得难"的内容）。按分位数切档，
每轮只从调度器指定的档位取样。

用分位数而非固定阈值的原因：不同语料、不同训练阶段的 loss 尺度差别很大，
固定阈值（如 <1 简单、>3 困难）换一份数据就失效。

### Q · 为什么温度必须铺开

n 次同温采样 ≈ 重复问同一个问题，信息高度冗余。温度铺开才能覆盖多个模式：

| 温度 | 拿到什么 |
|---|---|
| 0.3 | 教师最确信的模式（标准答案） |
| 1.3 | 教师认为"也说得通"的其他模式（软标签替代物） |

只用低温度 → 训练出死板的学生，只会一种说法
只用高温度 → 采样噪声大，一致性投票失效

### R · 一致性投票：黑盒唯一可靠的质量代理

这是整个方案最关键的一环。

白盒里，教师在某位置的分布自带不确定性信号：不确定时概率摊在多个 token 上。
黑盒只给文本，**答错时语气和答对时一模一样**，没有任何可用的置信度。

解法：同一问题在多个温度下采 n 次，按相似度聚簇：

- n 次答案高度一致 → 教师确信，可当软标签用
- 分裂成多个簇 → 要么问题有歧义、要么教师不会。黑盒无法区分这两者，
  所以统一保守处理（丢弃）

实测一致率与答案正确率的相关性在 **0.6~0.75** 之间，是目前黑盒场景下
最好的免标注质量代理。

一致性度量用**字符级 token F1** 而非分词后 F1：中文分词本身有歧义，
字符级对"用词覆盖率"的刻画更稳健。

聚类用**单遍贪心 + 与簇代表比较**而非与簇内所有元素比较——后者有
chaining problem（A≈B、B≈C 但 A≉C，会把两个不同答案合并）。

同时有三道退化检测：

| 检测 | 判据 |
|---|---|
| 纯复读 | 去重字符率 < 0.15（正常中文 > 0.4） |
| 周期复读 | 某短片段连续重复 ≥4 次且占全文 60%+ |
| 纯符号 | 字母/汉字占比 < 0.4 |

用**比例**而非绝对次数，这样短文本也能判出来。

### S · 能力匹配调度（ZPD）

白盒能实时看教师熵判断难度，黑盒只能靠学生 loss 反推。

```
loss > target_high  → 太难，降档（步长 2，更激进）
loss < target_low   → 太简单，升档（步长 1，保守）
区间内              → 保持
```

三个工程细节：

1. **滞回（hysteresis）**：动作后至少保持一轮。否则 loss 在阈值附近抖动会
   让档位来回跳，每轮问的题完全不同，学生学不到连续的东西。
2. **升降不对称**：降档比升档激进。太难会直接浪费整轮预算且损伤模型，
   太简单只是低效。
3. **档位轨迹是诊断信号**：

   | 轨迹 | 含义 |
   |---|---|
   | 始终在最低档 | ⚠ 学生没进步，该停下来查问题而不是继续烧预算 |
   | 稳步上升 | 正常进步 |
   | 反复震荡 | ⚠ 阈值区间过窄或 loss 方差过大 |

### U · 排序而非打分

黑盒做不了 GKD 那种"教师给学生 prefix 打分布"。替代方案是**排序**。

**为什么用排序而不是打分**：LLM 给的绝对分数在同一请求内可比，跨请求不可比
（同一个答案今天 7 分明天 8 分）。排序只需要相对偏好，天然免疫这个问题。
而且排序的输出空间小（k 个编号的排列），比连续分值更容易验证和解析。

**为什么排序优于"直接学教师答案"**：只学教师答案，学生学到的是"某一种正确
写法"；排序让学生看到自己的多个写法中哪个更好，学到的是**判别能力**——
泛化性显著强于单纯模仿。

偏好对只取 `最好 vs 最差` + `相邻对`，不做全排列：全排列产生 k(k-1)/2 个对，
其中大量是远距离对，信号强度和"第 1 vs 第 2"差不多但数量多得多，会淹没训练。
相邻对信息量最高（它们之间的偏好判断最难，最能刻画细粒度质量差异）。

DPO 的 β 要比 RLHF 常用值（0.1~0.5）偏小，因为教师排序也会错，
黑盒偏好对的噪声比人类标注大。

### V · 多教师域路由

集成不是"全都问"——黑盒按量计费，全问等于成本翻 N 倍。

核心假设：一个问题质量主要由**该域最强的教师**决定，而非所有教师的平均。
所以先用关键词规则判断域，只问最强的那一个。

用规则而非另一个 LLM 做域分类的三个理由：
1. **零成本**（不消耗黑盒预算——这是最关键的）
2. 可解释、可审计
3. 对粗粒度分类（代码/数学/写作/闲聊）准确率已够用（实测 14 个用例全对）

交叉验证只对 `cross_check_ratio` 比例的样本做。目的不是集成出更好答案，
而是**检测不可靠性**：两个强教师都答不出的问题，大概率不适合教学生。

## 快速开始

### 环境

```bash
pip install -r requirements.txt
```

需要本地有：
- 学生模型定义与基线权重（`D:\workspace\xllm\model\` 与 `out\full_sft_512.pth`）
- SFT 语料作为种子池（`D:\workspace\xllm\dataset\sft_t2t_mini.jsonl`）
- mock 模式下的本地教师：Qwen3-0.6B（见 `config.py` 的 `mock_model_path`）

> **关于权重文件**：本仓库**不包含**任何 `.pth` 权重（单个 116MB，超过 GitHub
> 100MB 硬限制，且训练产物不应进版本库）。`out/` 已在 `.gitignore` 中排除。
> 蒸馏产物需按下方命令自行训练生成。

### 无 API key：mock 模式

没有设置 `CHORUS_API_KEY` 时自动进入 mock 模式，用本地 Qwen3 模拟"只能
拿到文本"的受限通道。

**这不是降级，是刻意的设计**：mock 只暴露 `generate` 的文本输出，绝不返回
logits。任何依赖 logits 的逻辑会在 mock 下立刻暴露，不会等到线上才发现。

```bash
python train.py --num_rounds 1 --num_prompts 3 --n_samples 2 \
                --max_requests 40 --batch_size 1 --max_seq_len 256
```

### 真实黑盒 API

```bash
export CHORUS_API_KEY="sk-..."
export CHORUS_BASE_URL="https://api.openai.com/v1"
export CHORUS_MODEL="gpt-4o-mini"

python train.py --num_rounds 3 --num_prompts 100 --n_samples 5 --max_requests 2000
```

### 预算控制

**这是必须理解的机制。** 黑盒按量计费，一轮跑飞就超支。

```python
budget = Budget(max_requests=2000, max_tokens=2000 * 700)
# 超限抛 BudgetExceeded，而不是返回错误码
```

设计成**异常**而非返回值，是为了让调用方无法"忘了检查"。

一次 `n_samples=5` 的请求消耗 5 次 API 调用。100 题 × 5 = 500 请求。
在线策略每题额外 k+1 次。实际用量在日志里实时可见：

```
采样 3/3 | 59s | 预算 请求 6/60 (10.0%) | token 1626/42000 (3.9%)
```

### 推理

```bash
python infer.py --weight chorus_kd --prompt "用三句话解释什么是知识蒸馏。"
python infer.py --interactive
```

## 实测数据

单轮 3 题 × 2 采样（mock 模式）：

```
[种子] 24 条问句
[P 策展] 学生给 18 条候选打分 → 选中 3 题（档位 偏简单 2/5）
[Q 采样] 采样 3/3 | 61s | 预算 请求 6/40 (15.0%)
[R 筛选] 输入 3 条 → 保留 3 条 (100.0%) | 仅单采样 2 | 高一致 2
[T 组装] 3 条训练样本 | 平均学生 loss 2.070
[W 训练] iter 3/3 | ce 2.0704 → 完成后 train loss 1.634 | steps 1
[S 调度] 区间内保持 → 档位 偏简单 (2/5)
```

在线策略链路：

```
[U 在线策略] 在线策略 1/1 | 累计 3 个偏好对
[W 训练] DPO loss 0.7585 | margin -1.264 | pairs 3
```

`margin -1.264` 是负值，说明学生当前**更倾向 rejected**——这正是训练前
应有的状态，DPO 要做的就是把这个 margin 翻正。

## 实现中的坑

| 问题 | 现象 | 根因与修复 |
|---|---|---|
| **训练空转** | `steps 0`，loss 完全不动 | 3 条样本 + `grad_accum=4`，整轮一次 `opt.step()` 都没执行。尾批必须补 step |
| **device mismatch** | `Expected all tensors on same device` | `ce_loss` 内部索引 `ans_mask`/`w`，batch 必须整体搬 GPU 而非只搬 `ids` |
| **复读检测失效** | 22 字纯"哈"判不出来 | 长度阈值挡住了短文本。改用去重字符率（比例而非绝对次数）+ 周期检测 |
| **域分类漏判** | "写一个Python函数" → chat | 中文与字母间无词边界，`\b` 失效。改裸匹配 + 补中英文编程意图词 |
| **无意义串匹配** | `\b?` 报 `nothing to repeat` | 零宽断言不能重复。去掉 |
| **趋势误判** | 先降后升被判成"震荡" | 档位未变的 0 差值会隔断同向变化。先剔除 0 再算方向交替次数 |

## 与白盒蒸馏的分工

| 维度 | LensKD（白盒） | ChorusKD（黑盒） |
|---|---|---|
| 教师信号 | 完整 logits + hidden | n 次采样的文本 |
| 核心机制 | 双投影器跨词表对齐 | 一致性投票 + 排序 |
| 损失 | CE + 双路径 KL + 表征 | CE（多正例）+ DPO |
| 质量控制 | 熵门控逐位置自适应 | 自一致性投票（批量级） |
| 难度控制 | 实时看教师熵 | 学生 loss 反推 + 多轮调度 |
| 成本模型 | 一次性算力 | 按请求计费，必须熔断 |
| 主要风险 | 投影抹平分布 | 教师幻觉无法识别 |

两者不可互换，也不存在"哪个更好"——取决于你能拿到什么。

## 已知局限

1. **n 太小，分布估计很粗**。n=5 时频率估计的方差很大。这是黑盒的硬上限，
   只能靠一致性投票筛选而不能消除。
2. **一致性 ≠ 正确**。教师可能"一致地错"。相关性 0.6~0.75 意味着仍有
   25~40% 的错误无法识别。需要外部评测集做最终把关。
3. **域路由用关键词规则**，对边界模糊的问题（如"用 Python 解这道数学题"）
   会路由错误。可换小型分类器，但会引入额外成本。
4. **DPO 依赖教师排序质量**。mock 模式下教师（0.6B）排序能力有限，
   真实使用应换成强模型。
5. **未实现课程级的样本复用**。同一问题在不同轮次可能被重复问到，
   目前靠 `rng.shuffle` 降低概率，未做严格的去重追踪。
